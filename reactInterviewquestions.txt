1.What is React Fiber? How is it different from the old reconciliation algorithm?

React Fiber is a re-implementation of React’s reconciliation algorithm introduced in React 16.
Earlier, React used a synchronous stack-based reconciliation which blocked the main thread during large updates.
Fiber breaks rendering into small units of work, allows pausing, resuming, and prioritizing updates.
This makes React better at handling animations, user input, and large component trees without UI freezing.

2.How does React determine when to re-render a component?

React re-renders a component when its state, props, or context changes, or when its parent re-renders.
It compares previous and next values using reference checks and then runs reconciliation using the Virtual DOM.
A re-render doesn’t always mean a DOM update—React only updates the DOM when there’s an actual difference.

3.What  is the Concurrent feature in React?


Concurrent features in React allow rendering to be interruptible and priority-based.
React can pause low-priority updates, handle urgent user interactions first, and resume work later.
This improves responsiveness and prevents UI blocking, especially in large applications.

useTransition - Used to mark updates as low priority.
useDeferredValue - Delays updating a value until urgent work is finished.

4.What is React batching behavior? What changed in React 18?

Batching is React’s optimization where multiple state updates are grouped into a single render.
Before React 18, batching only worked inside React event handlers.
React 18 introduced automatic batching, so even updates inside async code like promises or setTimeout are batched,
resulting in fewer renders and better performance.
 
 
example:

Before React 18

✅ Batched (single re-render)

onClick={() => {
  setA(1);
  setB(2);
}}

❌ NOT batched (multiple re-renders)
setTimeout(() => {
  setA(1); // re-render
  setB(2); // re-render again
}, 1000);

After React 18

✅ Batched (single re-render)

setTimeout(() => {
  setA(1);
  setB(2);
}, 1000);

6.What is useImperativeHandle ?

useImperativeHandle is a React hook used with forwardRef to expose a controlled set of methods from a
child component to its parent.It’s useful for imperative actions like focusing inputs, opening modals, or
integrating third-party libraries, but should be used sparingly.
 
example


\

Parent Component:-


const ref = useRef();

<button onClick={() => ref.current.focus()}>
  Focus Input
</button>

<InputBox ref={ref} />


Child Component:-


import { forwardRef, useImperativeHandle, useRef } from "react";

const InputBox = forwardRef((props, ref) => {
  const inputRef = useRef();

  useImperativeHandle(ref, () => ({
    focus() {
      inputRef.current.focus();
    },
    clear() {
      inputRef.current.value = "";
    }
  }));

  return <input ref={inputRef} />;
});

7.How to handle large lists in React?

To handle large lists in React, I avoid rendering all items at once. I use list virtualization to render only 
visible items, pagination or infinite scrolling to reduce data size, and memoization to 
prevent unnecessary re-renders. I also ensure stable keys and optimized event handlers for performance.”

8.How does React handle hydration in SSR, and what problems can arise?

During SSR, React sends pre-rendered HTML to the browser. Hydration is the process where React attaches event handlers
and makes that HTML interactive.Problems arise when server-rendered HTML doesn’t match the client render, 
causing hydration mismatches, warnings, or full re-renders.

11.How to handle API errors gracefully in the UI

An Error Boundary is a React component that catches JavaScript errors in its child components during rendering and 
displays a fallback UI instead of allowing the entire component tree to crash.

For example, in our contract management dashboard, if the chart component crashes because of unexpected data, 
we can show an error message for that section while keeping the rest of the dashboard available.

UseEffect and useLayoutEffect

useEffect runs after the DOM is painted, so it does not block UI rendering. 
It is typically used for API calls, a timer, an event listner and subscriptions.

useLayoutEffect runs synchronously before the browser paints the screen,

useState 

useState is a React hook used to manage state inside functional components. Whenever the state value changes using 
its setter function, React schedules a re-render to update the UI

========================================================================================
useEffect

useEffect is a React hook used to handle side effects like API calls, event listeners, timers, and subscriptions. 
Based on the dependency array, it behaves in three ways.

1. Without dependency array
Executes after every render.
Whenever state or props change and cause a re-render, it executes again.

2.With empty dependency array []
Executes after the initial render (mount).
Commonly used for initial API calls.

3. With dependency array [count]
Executes after the initial render.
Executes again whenever count changes.

useRef is a React hook used to store a mutable value that persists between renders without triggering a re-render

useReducer

useReducer is a React hook I use to manage state when the state logic becomes more complex or when multiple state updates are related.

It works with a reducer function that receives the current state and an action, then returns the next state.

For simple state like a search input, I use useState. But for something like a form with loading, success, and error states, 
useReducer can make the logic easier to organize and maintain.

Redux Thunk 

Redux Thunk is a middleware that allows action creators to return a function instead of an action object.
It is used to handle logic with side effects, most commonly asynchronous operations like API calls, 
before dispatching actions to the Redux store.

Redux vs Context API 

In my React projects, I choose between Context API and Redux based on the complexity of the application and how the state is shared.

I use Context API for relatively simple global data, such as theme, language, or authentication information, 
where updates and state management are straightforward.

I prefer Redux Toolkit when the application has complex shared state, multiple components updating the same data, 
or more involved business logic

Microfrontend is an architecture where we split a large frontend application into smaller, independently developed and 
deployed applications. Each team can own a particular feature using React, and we combine those features into 
one user-facing application.

For example, in an enterprise application, we might have separate microfrontends for the dashboard, contract management, 
and user administration. Each team can develop and deploy its feature independently, instead of releasing the entire 
frontend every time.

---------------------------------------------------------------------------------------------------------------------------
how to run micro frontend or Module Federation


To run a microfrontend application, we usually run each microfrontend as a separate application on its own port during development, 
along with a host or shell application.

For example, in a React project using Module Federation, I would start the Products microfrontend on port 5001 and 
the host application on port 5000. The host loads the remote component through the remote entry file, so users can access 
everything through the host application.

In development, I run each application using npm run dev in separate terminals. In production, each microfrontend 
can be built and deployed independently, and the host loads it from its deployed URL.

Rules of hooks

React has two main rules for using hooks.

First, we should always call hooks at the top level of a functional component or custom hook. We should not 
call hooks inside conditions, loops, or nested functions.

Second, we should call hooks only inside React functional components or custom hooks, not inside normal JavaScript functions.

race conditions

Race condition happens when multiple asynchronous operations execute at the same time, and the final result depends on 
which operation completes first.

For example, in a search box, suppose I search for Chennai and immediately search for Bangalore. If the Bangalore API responds 
first but the Chennai API responds later, the old Chennai response might overwrite the latest Bangalore results.

To avoid this, I use techniques like AbortController, request cancellation, or request ID checking to ensure only the latest 
request updates the UI.

Feature Flags

I would use Feature Flags to enable or disable a feature in production without deploying new code.

For example, suppose we have an rent prediction chart feature in our Verizon Landlord Portal. If we notice any production issue 
with that feature, instead of rolling back the entire application, we can disable it using a feature flag.

We can maintain these flags in a backend configuration, database, or feature management tool. The React application checks 
the flag and conditionally displays the feature.

This allows us to control features independently without redeploying the frontend.

🔹 1. Authentication
Use secure authentication mechanisms such as JWT or session-based authentication to verify the user's identity.
🔹 2. Authorization
Authentication tells us who the user is. Authorization determines what the user is allowed to do.
For example, a normal user shouldn't be able to access admin-only APIs.
🔹 3. Input Validation
Never trust data coming from the client.
Validate request body, query parameters, and URL parameters before processing them.
🔹 4. Password Security
Never store plain-text passwords in DB.
Use strong password hashing algorithms such as bcrypt or Argon2.
🔹 5. API Rate Limiting
Limit how frequently a client can call your APIs.
This helps protect login, OTP, search, and other sensitive endpoints from excessive requests.
🔹 6. Protect Sensitive Data
Never expose:
• Passwords
• JWT secrets
• Database credentials
• API keys
• Private configuration

Use environment variables and proper secret management.
🔹 7. HTTP Security Headers
Use security headers to reduce common browser-based attacks.
For Express applications, middleware such as Helmet can help configure several security-related headers.
🔹 8. MongoDB Security
Use:
• Proper indexes
• Access controls
• Strong database credentials
• Network restrictions
• Safe query construction
Avoid directly trusting user input in database queries.
🔹 9. CORS Configuration
Don't blindly allow requests from every origin.
Configure CORS according to the domains that actually need access to your API.
🔹 10. Logging & Monitoring
Security doesn't end after deployment.
Monitor:
• Failed login attempts
• Suspicious API activity
• Server errors
• Unusual traffic
• Authentication failures
