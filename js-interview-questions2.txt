Execution Context

Execution context is the environment where JavaScript code is executed.
Each execution context has two phases: memory creation and execution.
In memory phase, variables are initialized with undefined and functions are fully hoisted.
Then in execution phase, values are assigned and code runs line by line.
JavaScript first creates the global execution context and then creates a new execution context for every function call.




💻 Example
var a = 10;
  
function test() {
  var b = 20;
  console.log(a + b);
}

test();

Memory Phase:
a = undefined
test = function(){}

Execution Phase:
a = 10
b = 20

When async operations like setTimeout,Promise,API calls are used, JavaScript sends them to Web APIs.

Hoisting

Hoisting means variable and function declarations are moved to the top of their scope during the memory creation phase.
Variables declared with var are hoisted and initialized with undefined, whereas function declarations are fully hoisted.


💻 Example

var a = 10;

Behind the scenes:
var a;
console.log(a);
a = 10;

Function Hoisting
test();

  console.log("Hello");
}


✔ Works because functions are fully hoisted.

Closures (⭐ MOST IMPORTANT ⭐)

“A closure is a function that remembers its lexical scope even after the outer function has finished execution.
Closures are commonly used for data hiding, maintaining state, and in cases like debouncing and currying.”

closures can contribute to memory leaks if a closure keeps references to objects that are no longer needed. 
The closure itself isn't a memory leak; the problem is when something remains reachable through the closure and 
therefore cannot be garbage-collected.

  let count = 0;

  function inner() {

  }

  return inner;

Debounce & Throttle

Debounce delays the function execution until the event stops firing, whereas throttle ensures a function is executed at regular intervals.
Debounce is useful for search inputs, and throttle is useful for scroll or resize events.
Both are used to improve performance and avoid unnecessary API call.

For example, in a search box, instead of calling the API for every keystroke, we wait until the user stops typing 

for 500 milliseconds and then make the API call.

💻 Example (Search Input)
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}


💻 Example (Scroll Event)
function throttle(fn, limit) {
  let inThrottle = false;

  return function (...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => {
        inThrottle = false;
      }, limit);
    }
  };
}

Polyfill

“map iterates over an array and returns a new array.
In the polyfill, this refers to the calling array.
We loop through the array, apply the callback, and push the result into a new array.”


1.Polyfill for map()

Array.prototype.myMap = function (callback) {
  let result = [];

  for (let i = 0; i < this.length; i++) {
    result.push(callback(this[i], i, this));
  }

  return result;
};

2.Polyfill for filter()

Array.prototype.myFilter = function (callback) {
  let result = [];

  for (let i = 0; i < this.length; i++) {
    if (callback(this[i], i, this)) {
      result.push(this[i]);
    }
  }

  return result;
};

3.Polyfill for reduce()

Array.prototype.myReduce = function (callback, initialValue) {
  let accumulator = initialValue;
  let startIndex = 0;

  if (accumulator === undefined) {
    accumulator = this[0];
    startIndex = 1;
  }

  for (let i = startIndex; i < this.length; i++) {
    accumulator = callback(accumulator, this[i], i, this);
  }

  return accumulator;
};

4.Polyfill for call()

Function.prototyp
e.myCall = function (context, ...args) {
  context = context || window;
  context.fn = this;
  context.fn(...args);
  delete context.fn;
};

5.Polyfill for apply()

Function.prototype.myApply = function (context, argsArray) {
  context = context || window;
  context.fn = this;
  context.fn(...argsArray);
  delete context.fn;
};

6.Polyfill for bind()

Function.prototype.myBind = function (context, ...args) {
  const originalFn = this;

  return function (...newArgs) {
    return originalFn.apply(context, [...args, ...newArgs]);
  };
};

shallow vs deep copy

A shallow copy copies only the first level of an object, so nested objects still share the same reference.
So, if I modify a nested object, the original object also gets updated.

A deep copy creates a separate copy of nested objects too, so changes in the copied object won't affect the original




1.example for shallow copy

const obj1 = { name: "JS", address: { city: "Chennai" } };

const shallow1 = Object.assign({}, obj1);
const shallow2 = { ...obj1 };

shallow1.address.city = "Bangalore";

console.log(obj1.address.city); // Bangalore ❗


2.example for deep  copy


const obj2 = { name: "JS", address: { city: "Chennai" } };

const deepCopy = JSON.parse(JSON.stringify(obj2));
deepCopy.address.city = "Bangalore";

console.log(obj2.address.city); // Chennai ✅

Memoization

Memoization is an optimization technique where we cache the result of expensive function calls 
and return the cached result when the same inputs occur again.


function memoize(fn){
  const cache = {}

  return function(n){
    if(cache[n]){
      return cache[n]
    }

    const result = fn(n)
    cache[n] = result
    return result
  }

Callback hell

Callback hell happens when we have multiple asynchronous operations that depend on each other, and we keep nesting callbacks 
inside callbacks. The code becomes difficult to read, maintain, and handle errors.

In a real project, imagine we need to fetch user details, then fetch their orders, and finally fetch payment details. If we handle
every step using nested callbacks, the code can become messy

We can avoid this using Promises or async/await.



=============================================================================================================================

Why are arrow functions not hoisted?

Actually, arrow functions are not hoisted in the same way as normal function declarations. If I store an arrow function in a 
const or let variable, the variable exists in the Temporal Dead Zone until its declaration is executed. So, if I try to call 
it before declaring it, JavaScript throws a ReferenceError.

In contrast, normal function declarations are fully hoisted, so we can call them before their definition.

Event delegation


Event delegation is a technique where a single event listener is attached
to a parent element to handle events for multiple child elements using event bubbling.

In my React or JavaScript applications, this is useful when rendering dynamic lists, because newly added 
items can also be handled without adding individual listeners
=============================================================================================================================
Event bubbling

Event bubbling means when I click a child element, the event starts from that child and travels upward to its parent elements. 
For example, if I click a button inside a div, the button's event fires first, then the parent div event fires.

Real-time use: Useful when we want a parent component to respond to events originating from its child elements.
============================================================================================================================
Event capturing


Event capturing is the opposite direction. The event travels from the outer parent elements down to the target element. 
We can enable capturing by passing true as the third argument to addEventListener.

Microtask and macrotask

A Microtask is a task that gets executed immediately after the current synchronous code finishes but before the next macrotask.
Microtasks have higher priority than macrotasks.

A Macrotask is a task that gets executed in the task queue after microtasks are completed.

Promise Chaning

Promise chaining is a technique where multiple .then() methods are attached to a promise so that 
asynchronous operations execute sequentially.

Each .then() returns a new promise, allowing the next operation to run after the previous one is completed.

Promise chaining helps handle multiple asynchronous operations in a sequential and readable way without creating nested callbacks.

Promise.all:
Will wait for all of the promises to resolve or any one of the promise 
reject.

Promise.allSettled:
Will wait for all the promises to settle (either fulfilled or rejected).


Promise.any:
Will return if any one of the promise fulfills or rejects when all the 
promises are rejected.

Promise.race:
Will return as soon as when any one of the promise is settled

Memory Leak

A memory leak in React happens when a component keeps references to resources like timers, event listeners, API calls,
or closures even after the component is unmounted, preventing garbage collection and causing unnecessary memory usage.

JavaScript automatically manages memory using garbage collection. The engine identifies objects 
that are no longer reachable from active references and removes them from memory. In Node.js, V8 mainly 
uses generational garbage collection, so short-lived objects are collected frequently and long-lived objects 
are handled differently

Interface and Type 

In TypeScript, both interface and type are used to define the structure of data and provide type safety.

I generally use interface for objects such as API responses, user details, or component props. 

I use type when I need something more flexible, like union types, intersection types, or defining a specific set of allowed values

Generics

Generics in TypeScript allow us to write reusable functions, components, and types that work with different data types 
while maintaining type safety.

For example, instead of writing separate functions for numbers and strings, I can create one generic function that 
accepts different types and returns the same type.

In React projects, I can use generics for reusable API response handlers.

Union (|)

Union type means a variable can accept more than one specified data type. We use the pipe symbol | to define it.

For example, in our application, a contract ID might come from an API as either a number or a string. Instead of using any, 
I can use a union type

=======================================================================================
Intersection (&)
Intersection type combines multiple types into one. It means the final object must contain all the properties defined in both types.

For example, if I have User and Employee interfaces, I can combine them to create an EmployeeDetails type.

unknown vs any in TypeScript

1. any – No type checking

When we use any, TypeScript allows us to perform any operation without checking the type.

2. unknown – Type checking required

unknown can also store any value, but before performing an operation, we must check its type.

Partial, Pick, and Omit

These are TypeScript utility types used to create new types from existing interfaces
example:
interface User {
  id: number;
  name: string;
  email: string;
  age: number;
}

1. Partial – Makes all properties optional
Useful when implementing update APIs where the user can update only a few fields.
Here, all properties become optional

2. Pick – Select specific properties
Useful when we need only selected fields from an existing interface.

3. Omit – Exclude specific properties
Useful when we don't want to expose sensitive fields, such as passwords, in a response type.
