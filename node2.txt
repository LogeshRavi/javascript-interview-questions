1.Difference between cluster and worker threads

In Node.js, Cluster and Worker Threads are both used to utilize multi-core CPUs, but they solve different problems.

Cluster creates multiple Node.js processes, each with its own event loop and memory.
It is mainly used to scale HTTP servers and handle more concurrent requests by distributing traffic across CPU cores.

Worker Threads run inside the same process but on different threads.
They share memory and are used for CPU-intensive tasks like data processing, encryption, or image manipulation.

In short, Cluster is for scaling requests, and Worker Threads are for heavy computation without blocking the event loop.

Cluster = more processes for more traffic
Worker Threads = more threads for heavy work

2.what is eventloop in nodejs and how it's diffrent from browser eventloop ?

The Event Loop is the mechanism that allows JavaScript to perform non-blocking asynchronous operations using a single thread.

In Node.js, the event loop is implemented by libuv. It continuously different phases like timers, 
I/O callbacks, poll, check, and close callbacks, and executes queued callbacks when the call stack is free.

This enables Node.js to handle thousands of concurrent requests efficiently without creating a new thread per request.

In contrast, the browser event loop is designed mainly for UI responsiveness. It manages DOM events, rendering, and user interactions along with 
async tasks like promises and timers.

While both use the concept of microtasks and macrotasks, Node.js has multiple event loop phases and also uses a thread pool for I/O operations,
which does not exist in the browser.

So overall, Node.js event loop is optimized for server-side concurrency, whereas the browser event loop is optimized for UI and rendering.

3.Difference between setTimeout, setImmediate, process.nextTick

In Node.js, these three differ based on when they execute in the event loop.

process.nextTick runs immediately after the current call stack, before the event loop continues. It executes before promises, 
timers, and I/O, so overusing it can block the event loop.

setTimeout schedules a callback in the timers phase after the specified delay, so it runs after microtasks and I/O polling.

setImmediate runs in the check phase, which is right after I/O callbacks, and is useful when we want to execute logic once 
I/O is completed.

So in short:

nextTick → highest priority

setTimeout → scheduled by time

setImmediate → after I/O

7.Libuv

libuv is a C library used internally by Node.js to handle asynchronous operations and manage the event loop.
Even though Node.js runs JavaScript in a single thread, libuv allows it to perform non-blocking I/O
operations like file system access, network requests, and timers.
So, in simple terms, libuv is the core reason why Node.js can handle multiple requests efficiently
despite being single-threaded.

8.Rate Limiting

Rate limiting is a technique used to control the number of requests a client can make to a
server within a specific time window.
It helps prevent abuse, DDoS attacks, and ensures fair usage of APIs.
In Node.js, we typically implement rate limiting using middleware like express-rate-limit,
where we define limits such as 100 requests per 15 minutes per IP.
For scalable systems, we use distributed stores like Redis to track request counts across multiple servers.
This ensures consistency and prevents users from bypassing limits in a load-balanced environment.

11.How would you scale a Node.js app for millions of users?

To scale a Node.js application for millions of users, I would focus on horizontal scaling since Node.js is single-threaded.

First, I would use clustering to run multiple instances of the app across CPU cores and servers.
Then, place a load balancer like Nginx or AWS ELB to distribute traffic efficiently.

I would introduce caching using Redis to reduce database load and improve response time.
For heavy or async tasks, I would use message queues like Kafka or RabbitMQ.

Finally, I would optimize the database using indexing, pagination, and possibly move to microservices if needed.



I would use auto-scaling to add instances when CPU, memory, or request traffic increases when there is suddern spike

12.How microservices communicate

Microservices communicate with each other mainly using two approaches: synchronous and asynchronous communication.

In synchronous communication, services use HTTP/REST APIs or gRPC, where one service directly calls another 
and waits for the response.

In asynchronous communication, we use message queues like Kafka or RabbitMQ, where services communicate 
via events without waiting for an immediate response.

In real-world systems, we prefer asynchronous communication for better scalability and 
fault tolerance, especially for background or heavy tasks.

16.Why Node.js is Single Threaded


Node.js follows a single-threaded event loop architecture.

Even though JavaScript runs in a  single thread, Node.js can still handle multiple requests simultaneously using asynchronous operations.

For example, if one API is waiting for database response, Node.js will not block the entire application. 
It will continue processing other requests.

This makes Node.js lightweight and scalable for I/O-heavy applications.

17.Streams

Streams process data in chunks instead of loading entire data into memory.

This improves performance and memory usage.

I mainly used streams for:

File uploads
Large file processing
CSV handling

To handle large file uploads efficiently in Node.js, I avoid loading the entire file into memory and
instead use streams to process the file in chunks.
I use libraries like multer or busboy which support streaming uploads.
The file is either stored directly on disk or uploaded to cloud storage like S3 using streams.
I also set file size limits, validate file types, and use chunked uploads for very large files.
For scalability, I handle uploads asynchronously and, if needed, process files using background jobs.

20.Buffer

A Buffer in Node.js is used to handle binary data directly in memory.

Since JavaScript does not natively support binary data, Node.js provides Buffer to work with raw data like files, 
network streams, or TCP data.

Buffers are fixed-size and are mainly used when dealing with I/O operations such as reading files or handling streams.

21.Slow API debugging

If an API is slow in production, first I would try to identify where the latency is coming from.
I would start by checking logs and monitoring tools to see response time patterns.

Then I would break down the API flow — whether the delay is in database queries, external API calls, or application logic.

I would use tools like APM (New Relic, Datadog) or add timing logs to measure each step.

If the issue is in the database, I would check query performance and indexing.
If it’s external APIs, I would add timeouts or caching.

Finally, I would optimize the bottleneck, deploy the fix, and monitor to ensure stability.

25.How do to secure API 
1. Authentication
Use secure authentication mechanisms such as JWT or session-based authentication to verify the user's identity.
🔹 2. Authorization
Authentication tells us who the user is. Authorization determines what the user is allowed to do.
For example, a normal user shouldn't be able to access admin-only APIs.
🔹 3. Input Validation
Never trust data coming from the client.
Validate request body, query parameters, and URL parameters before processing them.
🔹 4. Password Security
Never store plain-text passwords in DB.
Use strong password hashing algorithms such as bcrypt or Argon2.
🔹 5. API Rate Limiting
Limit how frequently a client can call your APIs.
This helps protect login, OTP, search, and other sensitive endpoints from excessive requests.
🔹 6. Protect Sensitive Data
Never expose:
• Passwords
• JWT secrets
• Database credentials
• API keys
• Private configuration
Use environment variables and proper secret management.
🔹 7. HTTP Security Headers
Use security headers to reduce common browser-based attacks.
For Express applications, middleware such as Helmet can help configure several security-related headers.
🔹 8. CORS Configuration
Don't blindly allow requests from every origin.
Configure CORS according to the domains that actually need access to your API.

27. how to perform search query if table have millions records

If I have lakhs of records, I would not scan the entire table for every search. First, I would identify 
the columns that are frequently searched and create indexes on them.  
For example, if users are commonly searched by email or user ID, I would create an index on those columns. 
I would also use pagination and select only the required columns instead of using SELECT *.  
I would check the query execution plan using EXPLAIN to make sure the index is actually being used. 
For very large datasets and complex searches, I could also consider caching with Redis or a search engine like Elasticsearch.

29.Access token and refresh token

Access token is a short-lived token used to access protected APIs or resources.
Refresh token is a longer-lived token used to get a new access token when the old one expires.
For example, after login, the application uses the access token for API requests, and when it expires, 
the refresh token is used to obtain a new one without asking the user to log in again.

30.Nodejs architecture

In my Node.js backend, I follow a layered architecture to keep the application maintainable and scalable.
The request first comes through the API/router layer, where I handle routing and middleware such as authentication, 
validation, logging, and rate limiting.
Then the request goes to the controller, which handles the HTTP request and response. The controller calls the service layer, 
where I keep the actual business logic.
The service layer communicates with the repository/data-access layer, which handles database operations with SQL or MongoDB.
I also keep common functionality like error handling, authentication, configuration, and logging in separate modules. For external services or background processing, I use APIs, Redis, or message queues depending on the requirement.
This separation gives us loose coupling, easier testing, maintainability, and scalability.

32.Unit test

Unit testing in Node.js means testing individual functions or modules in isolation to verify that they work as expected.
For example, if I have a service function that calculates an order total, I test different inputs and 
expected outputs without calling the actual database or external APIs.    
I can use frameworks like Jest, Mocha, or Vitest. For dependencies such as databases or third-party APIs, 
I mock them so the unit test focuses only on the function I'm testing.  
I also cover positive cases, negative cases, and edge cases.
